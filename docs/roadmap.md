# 전체 개발 계획

목표: 지원하는 Python 버전의 문법·내장 API·자료형·표준 라이브러리·오류·도구를
한글로 제공하고, 외부 패키지도 동일한 체계로 확장한다.
작은 실행 예제의 성공과 전체 언어 완성을 구별한다.

## 0.1 — 공개 기반

- [x] 공개 저장소, MIT 라이선스, 패키지 구조.
- [x] 전체 기본 키워드·공개 내장 이름·예외 번역 사전.
- [x] 언어 명세, 실행 구조, 번역어 참조 문서.
- [x] 어휘 변환, API 연결, 원본 위치, CLI.
- [x] 한글 모듈·패키지·동적 실행.
- [x] 표준 모듈 별칭과 버전별 전체 최상위 모듈 목록.
- [x] 일부 표준·NumPy·pandas API.
- [x] 기본 편집기 확장, CI, 패키지 생성.
- [x] 동등성·회귀·통합 시험.

완료 기준: 새 환경에서 설치하고 문서의 예제를 실행하며 모든 필수 검사가 통과한다.

## 0.2 — 문법과 호환성 강화

- [ ] 한국어 문맥 키워드를 사용 위치에 따라 정확히 구분.
- [ ] CPython 문법 테스트의 라이선스와 재사용 범위를 조사해 더 넓은 비교 코퍼스 구축.
- [ ] f/t 문자열·타입 매개변수·future 플래그·메타클래스·descriptor의 경계 사례 확대.
- [ ] 코드 객체·소스 조회·직렬화·multiprocessing 시작 방식별 검증.
- [ ] 번역어를 변경할 때 호환 별칭과 폐기 절차 도입.

완료 기준: 명세의 허용 문법에서 알려진 동작 차이를 목록으로 관리하고 필수 비교 코퍼스를 통과한다.

## 0.3 — 내장 API 전체

- [ ] 기본 자료형의 공개 멤버·허용 인자·속성·생성 인자 전체를 버전별로 조사.
- [ ] 특수 메서드·특수 속성의 기준 목록과 누락 검사.
- [ ] 모든 지원 API의 읽기·쓰기·삭제·호출·오류 동작 비교.
- [ ] 한글 도움말: 원문 이름, 인자명, 한국어 설명, 예제.

완료 기준: 버전별 공개 API 목록의 모든 항목에 번역·동작 시험·문서가 있고 조사 누락이 없다.

## 0.4 — 표준 라이브러리 전체

- [ ] 공개 하위모듈까지 전체 목록 구축.
- [ ] 모듈별 함수·클래스·멤버·키워드 인자 번역.
- [ ] 운영체제·선택 빌드 기능·버전 차이 표시.
- [ ] 입출력·통신·동시성·직렬화 등의 실제 사용 예제 검증.
- [ ] 번역어 검토와 자동 생성 후보를 분리해 관리.

완료 기준: 지원 버전의 공개 표준 API 전체에 검토된 번역이 있고,
플랫폼별 필수 검증과 예제·도움말이 갖춰진다.

## 0.5 — 오류와 개발 경험

- [ ] CPython 오류 메시지 템플릿 목록과 한국어 번역 체계.
- [ ] 라이브러리별 오류 설명 연결.
- [ ] 타입에 맞는 자동완성·정의 이동·이름 변경·진단.
- [ ] 원본 .han 기준 debugpy 중단점·단계 실행·변수 검사 통합.
- [ ] 설치·업데이트·프로젝트 생성 명령 정리.

완료 기준: 편집·실행·오류 이해·디버깅을 한글 소스 기준으로 수행한다.

## 외부 라이브러리 — 지속 확장

NumPy·pandas를 시작으로 사용자 수요에 따라 패키지별 번역팩을 추가한다.
각 번역팩은 지원 버전, 공개 API 목록, 번역된 비율, 통합 시험을 명시한다.
임의의 미래 패키지까지 번역 완료했다고 표시하지 않는다.

## 출시 정책

0.x에서는 번역어를 변경할 수 있다. 변경 내역과 이전 이름을 문서로 남긴다.
1.0은 문법·내장 API의 안정화와 검증 기준을 충족한 뒤 판단한다.
전체 생태계의 한국어 지원은 그 이후에도 계속 확장한다.
